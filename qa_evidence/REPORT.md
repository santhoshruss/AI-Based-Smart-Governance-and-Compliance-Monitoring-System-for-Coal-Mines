## Key Design Behavior Statements (D2b & D9c)

### 1. D2b: Voiding Inspections with Assigned Violations
- **Observed Behavior:** When an inspection has linked violations that have already moved to `ASSIGNED` or `IN_PROGRESS` (with active corrective actions), calling `PUT /api/inspections/:id/void` with `close_linked_violations: true` is **BLOCKED outright** with HTTP 400 (`Cannot void inspection: X violation(s) are already assigned or in-progress. Please verify/close those corrective actions first.`).
- **Rationale:** Prevents active worker assignments from becoming silent dangling references attached to voided inspections.

### 2. D9c: Dismissing Violations with Active Corrective Actions
- **Observed Behavior:** When attempting to dismiss an OPEN/IN_PROGRESS violation that already has an `ASSIGNED` corrective action, calling `PUT /api/violations/:id/dismiss` is **BLOCKED outright** with HTTP 400 (`Cannot dismiss violation: active corrective action(s) are already assigned or in progress. Please verify/close the action first.`).
- **Rationale:** Prevents worker tasks from being orphaned in the corrective actions pipeline while the parent violation is marked dismissed.
